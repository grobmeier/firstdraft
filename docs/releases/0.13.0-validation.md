# 0.13.0 desktop acceptance

Tested on 2026-10-04 in Obsidian 1.13.7, using only the isolated First Draft Test
Vault and disposable `Release QA` project with two explicitly ordered parts.

- Same-file Down moved a complete scene, synopsis and dialogue while keeping
  properties and `FADE IN:` in place. Native **Edit → Undo** restored the text.
  The automated Cmd+Z shortcut did not reliably act; native menu Undo did.
- Cross-part Confirm move wrote the destination scene and removed its source.
  Confirm restore restored both files to the recovery record's pre-move text.
- Adding later writing to the destination made recovery refuse the restore with
  an explicit conflict notice. The later writing and recovery record survived.
  After removing only the disposable test edit, recovery restored both files.
- Editing a source after opening Move produced “A screenplay changed. Refresh
  and try again.” No move was performed.
- Continuity inspection showed both project parts and source-linked optional
  dossier advice without modifying screenplay text.
- Authentic desktop screenshots were captured for both features.
- GitHub Dependabot alert #1 reports `fixed`; local dependency audit reports zero
  vulnerabilities.

Narrow-sidebar acceptance is **not verified**: automation could not reliably
resize the native pane. Physical iPhone testing is also deferred. Neither the
screenshots nor the automated tests prove mobile layout, undo, memory use or
performance. Repeat the scene and mobile checklists manually when possible.
